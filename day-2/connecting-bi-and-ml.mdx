## Why connect them?

Executives do not read Python scripts. They open a dashboard. For model results to change decisions, they need to appear where decision-makers already look.

{/* ILLUSTRATION I-22: Loop diagram: Data → Colab model → predictions CSV → Power BI dashboard → decision → new data. Each arrow clickable for one sentence of detail. */}

## Step 1: Export predictions from Colab

Add a column of predicted probabilities and download the file.

```python
df["predicted_viral_prob"] = model.predict_proba(df[features])[:, 1]

from google.colab import files
df[["track_id", "track_name", "track_genre", "popularity",
    "viral", "predicted_viral_prob"]].to_csv("predictions.csv", index=False)
files.download("predictions.csv")
```

<Warning>
These predictions are on tracks the model **already saw while training**, so they look better than they would on new songs. That is fine for a dashboard demo, but never use them to report model accuracy.
</Warning>

## The enterprise reality

In a real company the export step is automated: the model runs on a schedule, writes to a warehouse, and Power BI refreshes by itself. Analysts and executives interact only with the dashboard. Remember the **drift** from Day 1: someone still needs to monitor whether those predictions stay accurate.

export const Reveal = ({ question, answer }) => {
  const [show, setShow] = useState(false);
  return (
    <div className="my-3 rounded-xl border border-zinc-200 dark:border-zinc-700 p-4">
      <p className="m-0 font-medium">{question}</p>
      <button onClick={() => setShow(!show)} className="mt-2 px-3 py-1 rounded-md text-sm font-semibold" style={{ background: show ? "transparent" : "#1DB954", color: show ? "inherit" : "white", border: "1px solid #1DB954" }}>{show ? "Hide answer" : "Reveal answer"}</button>
      {show ? <p className="m-0 mt-2 text-sm">{answer}</p> : null}
    </div>
  );
};
